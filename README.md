# MEPhI SFU Server

Масштабируемый WebRTC медиасервер (Selective Forwarding Unit), написанный на Go с использованием библиотеки Pion. Проект предназначен для организации многопользовательских видеоконференций с поддержкой кластеризации и маршрутизации медиатрафика. Способен поддерживать 10 000+ одновременных видеопотоков на одной ноде и обеспечивает горизонтальное масштабирование.

## Суть и Логика Работы

SFU (Selective Forwarding Unit) принимает медиапоток от каждого участника (publisher) и перенаправляет (forward) его всем остальным участникам (subscribers) комнаты без транскодирования на стороне сервера. 

Логика работы сервера включает:
1. **Сигналинг:** Установка соединения по WebSocket для обмена SDP-предложениями (Offer/Answer) и ICE-кандидатами между клиентом и сервером.
2. **SFU-маршрутизация:** Получение входящих RTP-пакетов (видео/аудио) от клиента и рассылка этих пакетов всем подписчикам в той же комнате.
3. **Кластеризация (Опционально):** Синхронизация состояния комнат между нодами через Redis и каскадирование медиатрафика. Если участники одной комнаты подключены к разным нодам, ноды пересылают медиа-данные между собой.
4. **Событийная модель:** Асинхронная отправка событий (подключения, отключения, создание комнат) в брокер сообщений Apache Kafka.
5. **Встроенный TURN:** Обеспечение прохождения трафика через NAT (Network Address Translation).

## Архитектура и Стек Технологий

- **Язык программирования:** Go 1.25+
- **WebRTC Ядро:** Pion WebRTC
- **Хранилище состояний кластера:** Redis
- **Брокер событий:** Apache Kafka (KRaft mode)
- **Мониторинг:** Prometheus + Grafana
- **Контейнеризация:** Docker, Docker Compose

## Структура Проекта

- `cmd/sfud/` - Главный исполняемый файл сервера.
- `cmd/loadtest/` - Утилита для проведения нагрузочного тестирования (генерация WebRTC клиентов).
- `internal/sfu/` - Основная логика работы SFU (роутеры, комнаты, пиры, WebRTC-треки).
- `internal/cluster/` - Логика кластеризации, синхронизация через Redis и P2P каскадирование.
- `internal/signal/` - Сигнальный сервер (WebSocket).
- `internal/kafka/` - Продюсер событий в Kafka.
- `internal/turn/` - Встроенный TURN-сервер.
- `internal/metrics/` - Сбор метрик для Prometheus.
- `configs/` - Конфигурационные файлы (YAML).
- `deployments/` - Dockerfile, docker-compose.yml и конфигурации для Grafana/Prometheus.

## Предварительные требования

- Установленный Go (версия 1.25 и выше) для локального запуска и разработки.
- Docker и Docker Compose для запуска кластера и инфраструктуры (Redis, Kafka, Prometheus, Grafana).
- Утилита `make` для использования алиасов сборки и тестирования.

## Запуск и Тестирование

### 1. Полный демо-запуск кластера (Рекомендуется)

Команда `make demo` разворачивает всю инфраструктуру:
- 2 ноды SFU (порты 8080 и 8081)
- Redis
- Kafka
- Prometheus
- Grafana

```bash
make demo
```

После успешного запуска будут доступны:
- Мониторинг (Grafana): `http://localhost:3000` (Дашборды настроены автоматически)
- Prometheus: `http://localhost:9090`
- Сигнальные WebSocket серверы: `ws://localhost:8080/ws` и `ws://localhost:8081/ws`

Для остановки кластера используйте:
```bash
make demo-down
```

### 2. Нагрузочное тестирование (10 000+ потоков)

Проект включает мощную утилиту для нагрузочного тестирования. 
Чтобы продемонстрировать работу 10 000+ видеопотоков на одной ноде (105 клиентов, каждый транслирует и смотрит 104 других), выполните:

```bash
make docker-loadtest-10k
```
Результаты нагрузки (CPU, память, кол-во пакетов, задержки) можно отслеживать в реальном времени в Grafana.

Для тестирования горизонтального масштабирования (каскадирования между двумя нодами кластера, ~21 000 потоков) выполните:

```bash
make docker-loadtest-cluster
```

### 3. Локальная разработка (Standalone запуск)

Для разработки можно запустить SFU локально без Docker:

1. Скопируйте или измените конфигурационный файл из `configs/config.yml` (или используйте `configs/loadtest.yml`).
2. Запустите сервер:
```bash
make run-server
```

Запустить быстрый smoke тест локально (5 клиентов):
```bash
make smoke-test
```

Для локального нагрузочного тестирования с произвольными параметрами:
```bash
make run-loadtest CLIENTS=50 RAMP=5 DURATION=30s
```

## Конфигурация

Конфигурация сервера осуществляется через YAML-файлы. Основные разделы конфигурации:

- `server:` Настройки HTTP/WebSocket (хост, порт, таймауты).
- `sfu:` Лимиты комнат, интервалы PLI (Picture Loss Indication).
- `ice:` Настройки STUN/TURN серверов для обхода NAT.
- `cluster:` Активация кластерного режима, подключение к Redis.
- `metrics:` Настройки экспорта метрик для Prometheus.

Пример структуры можно найти в файле `configs/config.yml`.
